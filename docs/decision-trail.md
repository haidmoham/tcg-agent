# Initial simulator milestone

## Acceptance predicate

On the Windows desktop, run complete CPU-only games in an explicitly admitted card profile. Verify legal decisions, hidden-information isolation, three terminal reasons, deterministic replay and interleaved environments. Save repeated throughput measurements with consumed work counts and a separate profile. Deliver a standalone explanatory HTML file. Preserve the original project and keep private data out of publication.

## Bounded workflow and decisions

1. Inspect local and connected GitHub projects before choosing an architecture. Found the October 18 project and reused its identity. The earlier competition scaffold is a different project.
2. Audit all advertised refs and complete reachable trees before public visibility. Both existing commits contain only the README and ignore file. Existing author metadata remains visible in Git history.
3. Compare a broad retained-engine adapter with a closed kernel. Chose a small public kernel because complete prompt and RNG auditing would exceed the first milestone. No code from private projects was copied. A broader adapter remains an evidence-gated next step.
4. Implement the smallest complete game profile. The state model is a private two-player phase machine with explicit decision objects, a factual card registry and per-game randomness. Unsupported printings throw.
5. Run behavior tests before measurement. Early failing checks were fixture mistakes: one seed lacked a benched retreat target, and a conservation check tried to count deliberately hidden setup Pokémon. Corrected those checks without weakening the visibility boundary.
6. Independent review found and fixed opening-hand information before first-player selection, boxed-string card-ID admission and the missing public first-player declaration. Restricted the extra setup bench stage to bonus-drawn Basics.
7. Inspect sampled seeds before freezing the benchmark. Replaced the initial un-mixed small-seed RNG initialization with a counter-plus-integer mixer so adjacent seeds do not force the same opening coin result. The test suite pins its sequence and complete-game behavior.
8. Benchmark developed games as well as offering a short-game option. Delaying attacks until turn 50 is an explicit stress workload, not a competitive policy. It exercises 6-prize wins and developed boards rather than advertising a throughput dominated by immediate knockouts.
9. Run a separate profiler and preserve the unprofiled repeated measurement. Profiling writes a different output path so it cannot overwrite the benchmark receipt.
10. Verify tutorial controls, desktop/mobile rendering and offline operation. The temporary preview binds loopback only. The normal sandbox isolated browser access, so the approved host preview was used.

The learner's prediction and interpretation have not been supplied by an agent. No training objective or learned policy has been implemented on the learner's behalf. The tutorial identifies the next places where the learner's hypotheses, debugging and mathematics should decide the experiment.

## Scope of the proof

Tests establish the implemented contracts and selected rule fixtures. They are not an exhaustive rules certification or a differential comparison against TCG Live. Throughput is for this historical three-card profile and CPU policies. It does not estimate full Standard or neural training performance. No Live match, credential action, paid compute or GPU training occurred.
