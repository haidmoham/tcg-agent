# Thin official-client observation service

This document records the earlier pixel/OCR readiness stage. The separate scoped runtime adapter later entered one built-in AI game; the [pilot receipt](official-client-ai-pilot.json) and [sample report](official-client-sample.md) describe that user-stopped attempt. No continuation or new game is authorized. The service described here remains read-only and does not itself provide playing observations.

`node scripts/official-client-observe.mjs .cache/client-ui-config.json` starts a read-only loopback service. The configuration pins absolute installed Python and PowerShell executables, the current official-client process ID and window handle, and the exact deck display name `AgentPult`. Rediscover process and window identity after a client restart. Captures use the separately verified normal Windows adapter; OCR uses already installed RapidOCR and its bundled ONNX files. No installation, account change, client modification, or game entry is required.

The service prints an ephemeral `http://127.0.0.1:<port>` address and stores it in ignored `.cache/observation-service.json`. It preserves captures, OCR results, and recognition receipts only under ignored `.cache/service-observation-*`. Its HTTP response excludes paths, screenshots, raw OCR text, account names, and arbitrary source fields. No captured private assets are committed or uploaded.

```powershell
$service = Get-Content .cache/observation-service.json -Raw | ConvertFrom-Json
Invoke-RestMethod ($service.url + '/health')
Invoke-RestMethod ($service.url + '/observation')
```

`GET /battle-log` additionally exposes an optional sanitized receipt for [private exportable battle-log recording](official-client-battle-log.md). Configure `battleLogExportFile` to consume an existing private export file; the observation service itself does not attach to the client. There is no input, arm, model execution, file-serving, or clipboard route. Requests with an Origin header, a foreign Host header, a body, or a mutation method are rejected. The listener binds only IPv4 loopback, sends `Cache-Control: no-store`, and limits connections and request duration. Loopback is a same-desktop convenience boundary; the service does not claim to protect against other local processes running as the user.

Capture and OCR run serially with a two-second interval after completion. The service stops after two minutes or 60 observations, whichever comes first; this is a bounded readiness probe. It owns and stops its OCR child and capture wrappers. SIGINT/SIGTERM stops it early. The existing `.cache/official-client.kill` marker also prevents subsequent captures. It does not alter other UI servers.

`/health` reports starting, observing, or capture-blocked. `/observation` reports capture time, age, image hash, dimensions, verified window identity and focus, recognized screen, exact selected deck display name when visible, safe navigation targets, and explicit unknowns. It always reports `inputsEnabled: false`, `gameplayReady: false`, and `policyView: null`. Responses older than five seconds return HTTP 503 with `stale: true`; failed captures invalidate the last observation and return a fixed error. No previous good state becomes a substitute for a failed new capture.

The driver now checks clipping and foreign capture before any global event, verifies actual cursor position after movement, and rechecks ownership and foreground before pressing. No capture release, clip change, foreground-lock workaround or client modification is used. The user has been asked to switch to the client once so capture can clear before the next single navigation test.

## Reusing the local DATAMINE

The inspected local research already provides exact card programs, native player-safe projection contracts, selection constraints, and final-versus-incremental input semantics. The existing Indigo/native worker projection belongs to its offline game instance. Its engine bridge contract is a source-bound recommendation, not an attached export from the running official client.

The [source audit](official-client-runtime-audit.md) identifies exact event interfaces and the source fingerprints of twelve relevant files. `NetworkMatchController.BeginSendingClientEventsTo` and `ClientMatchMainThreadEventSystem.SendEventsTo` register in-process listeners. `IBattleLogStateProvider` exposes presentation events; `BattleLogExporter` writes an ordinary user-triggered export to the clipboard. No inspected source establishes an external current-state endpoint. The existing runtime-query tool attaches Frida and extracts session credentials; it is excluded and was never executed. Standard UI Automation exposed no Unity controls. The HTTP observation explicitly reports `source.kind: visible-window-capture`, `structuredMatchAttached: false`, and `policyView: null`.

Run the focused checks with `node --test tests/official-client-recognize.test.mjs tests/official-client-observation-service.test.mjs tests/official-client-bridge.test.mjs`. Local HTTP tests require ordinary loopback access; the restricted execution sandbox returned `EACCES`, and the same tests passed in the approved desktop execution context. Tests cover route authority, browser/Host rejection, stale state, error redaction, bounded lifetime, non-overlapping capture, anchored recognition, and existing supervisor behavior.
