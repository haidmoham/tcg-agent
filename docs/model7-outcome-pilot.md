# Fixed-deck outcome PPO pilot

The first approved run completed: four updates from 24 natural training games yielded 1,709 on-policy decisions and 67 optimizer steps. Validation was 1–7. Fresh paired confirmation was 22–42, score 0.34375, with the predeclared 32-block 95% interval [0.1036693022, 0.5838306978]. All 64 confirmation games completed naturally without invalid blocks, forfeits, command caps or command rejections. The result does not demonstrate improvement over frozen Model6; the lower point estimate is not a conclusive proof of deterioration. No promotion or further training followed. See `model7-outcome-pilot-result.json` for exact pins, counts and timings, and `../repro/model7-outcome-001/` for the two executed authored source overrides.

The useful conclusion is specific to this small continuation: it completed valid outcome learning and complete-game evaluation, but produced no evidence to replace Model6. It trained 1,316 ordinary decisions and 393 mandatory singleton selections; another 250 selection-ranker decisions and 185 helper decisions remained frozen. Parameter updates and the 11-13 training score do not identify a strategic improvement. The result does not isolate whether data volume, outcome credit assignment, existing representation or the frozen selection/helper route limited performance. That diagnosis requires decision evidence rather than another automatic run of the same recipe.

The successful run lasted 51 minutes 2.278 seconds: 858.827 seconds collecting, 81.050 seconds fitting, 227.621 seconds validating and 1,893.477 seconds confirming, plus orchestration overhead. All 96 planned games finished naturally. Original checkpoints and the final candidate were retained, and every file in the private 774-file archive was verified against its copy on the larger model drive. Public source contains no checkpoints, raw records or native prerequisites.

`scripts/run-model7-outcome.mjs <private-manifest>` coordinates one explicitly approved pilot using the existing native collector and PPO update service. It requires a fresh output, an approved manifest and the original natural-terminal reward: win1, draw0, loss−1, nonterminal0. It uses no external demonstrations, replay reconstruction, search labels or client inputs. Private manifests, native prerequisites, catalogs, records and weights stay outside publication.

The fixed protocol is24 training games in four six-game collection/update batches, two CPU collection lanes, and an unchanged frozen optional/multi-card selector. Twelve games face frozen Model6 update23; twelve face the pinned existing heuristic, balanced across seats. Each batch requires six qualified natural completions before updating. Collection is limited to30 minutes and fitting to two minutes total. The final fourth batch update is fixed before evaluation; intermediate results do not select a checkpoint.

The collector's explicit `baselineOpponentKind:'ppo'` uses `EntityPpoModelClient` for the frozen opponent, with a required checkpoint pin and matching frozen-selection pin. Its mandatory single-card prompts validate every offered singleton before deterministic selection by that actor. Optional/multi-card prompts use the separate frozen selector. Remaining unsupported helper decisions fall through to the common pinned native policy. The legacy opponent path stays available when the new kind is absent. The retained exact Hammerpult pilot recipe has its own explicit hash; it does not admit arbitrary decks.

The learner records only its actually sampled, accepted ordinary and supported singleton choices, with old log probabilities/values. Unlearned rankings/helpers remain attributed separately. Incomplete or failed trajectories cannot become outcome rewards. The existing initial collector requires an identified winning seat and would exclude a missing winner rather than invent a natural draw. Source/checkpoint/legality/privacy guards remain active. Runtime core files must match the original checkpoint source hashes; the pilot resumes copied actor, critic and matching optimizer without a reward remap or optimizer reset.

After four updates, eight fresh validation games precede32 fresh paired confirmation blocks against unchanged Model6. Both seats share the same exact deck and frozen selector/helper versions. The confirmation uses the existing comparator with a separately versioned `model7-outcome-pilot-final-bundle/1` receipt; it does not pretend PPO is a BC fit. Policy failures are forfeits, common command caps are separately reported draws, and shared harness failures invalidate entire blocks with a bounded predeclared replacement reservoir. Validation is capped at ten minutes; confirmation at90 minutes. An absolute overall deadline survives preparation retries, with a maximum135-minute run. Any incomplete phase remains explicitly incomplete.
